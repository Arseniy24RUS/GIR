# Data Lab: каталог данных и универсальный Data Explorer

## Назначение

Data Lab — публичный исследовательский контур платформы Global Index Research. Он раскрывает не только итоговые индексы, но и доказательную базу проекта: источники, версии файлов, нормализованные наблюдения, преобразования и режимы распространения.

Раздел доступен по маршруту `/data-lab` и не использует тяжёлый `/api/app-data`. Каталог и Explorer загружаются отдельными API-запросами только после открытия страницы.

## Информационная модель

### Dataset

Содержательно единый источник или статистическая система. В пользовательском интерфейсе dataset представлен карточкой организации-источника, временным охватом, числом наблюдений, связанными индексами и статусом прав.

### Snapshot

Зафиксированное состояние источника на дату получения. Snapshot связан с официальным URL, датой получения, локальным путём и SHA-256.

### Distribution

Конкретный файл, доступный пользователю или зарегистрированный в доказательной базе: PDF, CSV, XLSX, JSON, производная выгрузка, recipe, manifest или иной артефакт воспроизводимости.

### Observation

Страново-временное значение аналитического показателя. Observation не тождественен raw-файлу: это нормализованная запись, полученная после импорта и гармонизации.

## Режим распространения

Сервер принимает решение на уровне каждой дистрибуции.

1. **Downloadable** — файл разрешён к просмотру и скачиванию после проектной проверки прав.
2. **Restricted raw** — файл присутствует в поставке и участвует в расчётах, но публичная выдача запрещена. Интерфейс показывает метаданные, официальный URL, checksum и разрешённые альтернативы.
3. **Metadata only** — файл зарегистрирован, но отсутствует в текущем deployment или не предназначен для публичного распространения.

Неизвестный или неоднозначный правовой статус трактуется консервативно. Наличие файла на диске само по себе не разрешает его публичную выдачу.

## API

### Каталог

- `GET /api/data-catalog/summary`
- `GET /api/data-catalog/sources`
- `GET /api/data-catalog/sources/{source_id}`
- `GET /api/data-catalog/files`
- `GET /api/data-catalog/files/{file_id}`
- `GET /api/data-catalog/files/{file_id}/preview`
- `GET /api/data-catalog/files/{file_id}/content`
- `GET /api/data-catalog/manifest.csv`
- `GET /api/data-catalog/dcat.jsonld`

`file_id` является непрозрачным серверным идентификатором. Клиент не передаёт файловый путь, поэтому маршрут нельзя использовать для path traversal.

### Data Explorer

- `GET /api/data-explorer/schema`
- `GET /api/data-explorer/query`
- `GET /api/data-explorer/export.csv`
- `GET /api/data-explorer/datasets/{dataset_id}/metadata.json`
- `GET /api/data-explorer/provenance/{value_id}`

Все имена таблиц, колонок и показателей выбираются из серверного whitelist. Параметры пользователя передаются в SQL только как bind-параметры.

## Поддерживаемые аналитические слои

Набор публикуется только в том случае, если соответствующая таблица и обязательные колонки реально существуют в SQLite.

- итоговые индексные оценки;
- компоненты официальных индексов;
- исходные нормализованные наблюдения;
- компоненты HTEI v6;
- итоговая модель конкурентоспособности подготовки кадров;
- блоки и компоненты модели подготовки кадров;
- QS Engineering & Technology;
- национальная статистика;
- корпоративные показатели.

Такой подход позволяет расширять базу без ручного создания новой страницы для каждого источника.

## Визуальные представления

Explorer поддерживает:

- временную линию;
- горизонтальные столбцы последних доступных значений;
- scatterplot;
- распределение;
- точную таблицу;
- CSV-экспорт текущей выборки.

Состояние исследования сохраняется в URL. Существенные значения видны без hover; tooltip используется только как дополнительный способ прочитать точную точку.

## Ограничения безопасности и производительности

- JSON-представление ограничено 5 000 строками;
- CSV-экспорт ограничен 100 000 строками;
- preview читает только первые строки или ограниченный объём текста;
- путь файла разрешается только внутри корня проекта;
- raw-файл никогда не выдаётся только на основании его физического наличия;
- SQLite используется в режиме чтения на уровне логики модуля: каталог не создаёт и не изменяет таблицы.

## Воспроизводимость

Каталог публикует:

- CSV-манифест дистрибуций;
- DCAT JSON-LD;
- CSVW-подобные схемы аналитических таблиц;
- SHA-256;
- `source_id`, `snapshot_id`, `artifact_id` и `value_id`;
- provenance отдельного наблюдения.

## Обновление

Новая загрузка должна быть зарегистрирована в существующих таблицах `source_registry`, `raw_snapshots` и `reproducibility_artifacts`. Новый аналитический слой становится доступным Explorer после добавления whitelist-описания в `giip/data_lab.py`; копировать данные в отдельную каталогную таблицу не требуется.
